1 Infraestrutura de Testes

O projeto utiliza o Vitest como framework de testes unitários — uma ferramenta nativa do ecossistema Vite, compatível com a API do Jest, que executa os testes diretamente no ambiente de módulos ES sem transpilação extra.

1.1 Arquivo de Configuração

vitest.config.ts 
import { defineConfig } from 'vitest/config'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
  test: {
    globals: true,          // describe/it/expect disponíveis sem import
    environment: 'node',    // ambiente Node.js (sem DOM)
    include: ['src/**/*.test.ts', 'src/**/*.test.tsx'],
    coverage: {
      reporter: ['text', 'html'],
      include: ['src/utils/**', 'src/services/**'],
    },
  },
})
Por que environment: 'node'? Os testes cobrem funções puras de cálculo e transformação de dados. Não há renderização de componentes React, então o ambiente Node é suficiente e mais rápido que jsdom.

1.2 Scripts npm Disponíveis

package.json 
"scripts": {
  "test":          "vitest run",           // executa uma vez e sai
  "test:watch":    "vitest",               // modo watch (reexecuta ao salvar)

  "lint:fix":      "eslint \"src/**/*.ts\" \"src/**/*.tsx\" --fix"

2 Testes Unitários — userUtils

src/utils/userUtils.ts

Contém a função initials, responsável por extrair as iniciais do nome de um usuário para exibição em avatares.

2.1 Código-Fonte da Função

src/utils/userUtils.ts 
export function initials(name: string): string {
  return name
    .split(' ')
    .filter(Boolean)       // remove tokens vazios (espaços extras)
    .slice(0, 2)           // usa apenas as 2 primeiras palavras
    .map((w) => w[0].toUpperCase())
    .join('');
}

describe('initials', () => {

    expect(initials('João Silva')).toBe('JS');
  });

  it('retorna apenas a inicial quando há um único nome', () => {
    expect(initials('Ana')).toBe('A');

3 Testes Unitários — analyticsService

O analyticsService.ts é o núcleo de cálculo da plataforma. Ele converte respostas brutas do Firestore em pontuações por domínio TPACK, séries temporais de evolução, dados comparativos e classificações de status. São 27 testes em 9 suítes, todos isolados do Firebase.

3.1 Helper de Fábrica — makeResponse

Todos os testes que precisam de um QuestionnaireResponse usam o helper makeResponse, definido no topo do arquivo de teste. Ele aceita um mapa plano de respostas Record<string, number> e o converte para o formato Answer[] que o serviço espera.

src/services/analyticsService.test.ts — linhas 19–32 
function makeResponse(
  rawAnswers: Record<string, number>,
  overrides: Partial<QuestionnaireResponse> = {},
): QuestionnaireResponse {
  return {
    id: 'test-id',
    questionnaireId: 'q-default',
    userId: 'user-default',
    schoolId: 'school-default',
    answers: Object.entries(rawAnswers).map(([questionId, value]) => ({ questionId, value })),
    completedAt: new Date(),
    ...overrides,
  };
}
Por que este helper existe? QuestionnaireResponse requer vários campos obrigatórios. Sem o helper, cada teste repetiria 6+ linhas de boilerplate. O segundo parâmetro overrides permite sobrescrever qualquer campo (ex.: userId, completedAt, segment) sem perder os defaults.

3.2 Suíte: answersToScores

Converte um mapa Record<string, number> de respostas em pontuações por domínio TPACK (8 domínios: TK, PK, CK, TPK, TCK, PCK, TPACK, e mais). Ignora valores 0, calcula médias e arredonda para 2 casas decimais.

src/services/analyticsService.test.ts — linhas 39–70 
describe('answersToScores', () => {
  it('calcula a média correta por domínio', () => {
    const answers = { tk1: 4, tk2: 2 }; // média tk = 3.00
    const scores = answersToScores(answers);
    const tk = scores.find(s => s.domain === 'tk');
    expect(tk?.score).toBe(3);
  });

  it('retorna 0 para domínios sem respostas', () => {
    const scores = answersToScores({});
    expect(scores.every(s => s.score === 0)).toBe(true);
  });

  it('ignora valores iguais a 0 no cálculo', () => {
    const answers = { tk1: 4, tk2: 0 }; // tk2=0 ignorado → média = 4
    const scores = answersToScores(answers);
    const tk = scores.find(s => s.domain === 'tk');
    expect(tk?.score).toBe(4);
  });

  it('retorna um score para cada domínio definido', () => {
    const scores = answersToScores({});
    expect(scores.length).toBe(8); // 8 domínios TPACK
  });

  it('arredonda para 2 casas decimais', () => {
    const scores = answersToScores({ pk1: 5, pk2: 4 });
    const pk = scores.find(s => s.domain === 'pk');
    expect(pk?.score).toBe(4.5);
  });
});

3.7 Suíte: buildEvolutionData

Constrói a série temporal de evolução do professor, convertendo cada resposta em um ponto com campo period (ex.: "jun/24") e scores por domínio. Os pontos são ordenados por data crescente.

src/services/analyticsService.test.ts — linhas 162–187 
describe('buildEvolutionData', () => {
  it('retorna array vazio para entrada vazia', () => {
    expect(buildEvolutionData([])).toEqual([]);
  });

  it('ordena por data crescente', () => {
    const older = makeResponse({ tk1: 3 }, {
      id: 'r-old',
      completedAt: { seconds: 1000, toDate: () => new Date(1000000) } as any,
    });
    const newer = makeResponse({ tk1: 4 }, {
      id: 'r-new',
      completedAt: { seconds: 2000, toDate: () => new Date(2000000) } as any,
    });
    const result = buildEvolutionData([newer, older]);
    const tkLabel = 'Conhecimento Tecnológico';
    expect((result[0] as any)[tkLabel]).toBeLessThan((result[1] as any)[tkLabel]);
  });

  it('gera um ponto por resposta com campo period', () => {
    const r = makeResponse({ tk1: 3, tk2: 3 });
    const result = buildEvolutionData([r]);
    expect(result).toHaveLength(1);
    expect(result[0].period).toBeDefined();
  });
});
Simulando Firestore Timestamp: O campo completedAt no Firestore não é um Date puro, mas um objeto { seconds: number }. O teste simula isso passando { seconds: 1000 } via overrides para validar que o serviço converte corretamente ambos os formatos.

4 Correção Aplicada — makeResponse

4.1 O Problema

Ao rodar os testes pela primeira vez, o Vitest retornou um erro que impedia a execução da suíte inteira: 

FAIL  src/services/analyticsService.test.ts
ReferenceError: makeResponse is not defined
 ❯ src/services/analyticsService.test.ts:226:21
    224| const teachers = [...]
    225| const responses = [makeResponse({}, { userId: 'prof1', questionnaireId: 'q1' })];
       |                   ^
Causa raiz: A seção // ── Helpers ─── no topo do arquivo de teste estava vazia. A função makeResponse era referenciada em múltiplos describe mas nunca havia sido definida — o bloco de código foi deletado ou nunca foi escrito.

4.2 Por que o erro era grave

O erro ocorre em nível de módulo (fora de um it()), na linha: 

const responses = [makeResponse({}, { userId: 'prof1' })]; // nível do describe

Como o JavaScript avalia esse código ao carregar o módulo, toda a suíte falha antes de executar qualquer teste — não apenas o teste onde o helper é chamado. Isso explica a mensagem Tests: no tests no relatório do Vitest.

4.3 A Solução

Foi adicionado o helper makeResponse na seção de helpers (linhas 19–32 do arquivo), com tipagem completa e suporte a overrides:

src/services/analyticsService.test.ts — adicionado nas linhas 19–32 
function makeResponse(
  rawAnswers: Record<string, number>,
  overrides: Partial<QuestionnaireResponse> = {},
): QuestionnaireResponse {
  return {
    id: 'test-id',
    questionnaireId: 'q-default',
    userId: 'user-default',
    schoolId: 'school-default',
    // converte { tk1: 4, tk2: 2 } → [{ questionId: 'tk1', value: 4 }, ...]
    answers: Object.entries(rawAnswers).map(([questionId, value]) => ({ questionId, value })),
    completedAt: new Date(),
    ...overrides,
  };
}
Resultado: Após a correção, todos os 33 testes passaram em 324ms. O erro ReferenceError foi eliminado e nenhum teste foi alterado — apenas o helper foi criado.

7.2 Comandos Customizados — cypress/support/commands.ts

cypress/support/commands.ts 
/** Login via formulário — reutiliza sessão entre testes do mesmo perfil */
Cypress.Commands.add('loginAs', (role: 'professor' | 'gestor' | 'secretaria') => {
  const emails    = { professor: Cypress.env('TEST_PROFESSOR_EMAIL'), ... };
  const passwords = { professor: Cypress.env('TEST_PROFESSOR_PASSWORD'), ... };

  cy.session([`auth-${role}`], () => {
    cy.visit('/login');
    cy.get('[data-testid="email-input"]').type(emails[role]);
    cy.get('[data-testid="password-input"]').type(passwords[role]);
    cy.get('[data-testid="login-submit"]').click();
    cy.url().should('include', `/app/${role}/inicio`);
  });
});

/** Intercepta chamadas Firebase Auth com fixture mockada */
Cypress.Commands.add('stubFirebaseAuth', (fixture) => {
  cy.intercept('POST', '**/accounts:signInWithPassword**', {
    statusCode: 200,
    body: { idToken: 'mock-id-token-' + fixture.role, ... },
  }).as('firebaseLogin');
});

/** Aguarda desaparecimento do spinner de loading */
Cypress.Commands.add('waitForPage', () => {
  cy.get('[data-testid="loading-spinner"]', { timeout: 10000 })
    .should('not.exist');
});
